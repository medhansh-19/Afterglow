# Afterglow desktop interface

The Linux and Windows ports share the existing local Canvas/SVG listening surface. This port preserves its established dark palette, Manrope typography, graph, glow and ribbon identity; it introduces no visual redesign. `src/style.css` owns runtime visual tokens and geometry, `src/clock-preview.js` owns seven clock faces, and `src/render.js` owns playback and frozen map rendering. Mac source `Sources/Afterglow` and the original Mac workspace DESIGN.md define intended feature behavior.

The listening surface displays synchronized words as a graph. Untimed lyrics remain in the explicitly opened library. Provider and timing diagnostics belong in that library. Appearance and clock fields use native HTML input/select controls, including operating-system-owned popup geometry and keyboard behavior. Preserve reduced motion, native keyboard focus and bounded panel scrolling.

`src/domain.js` owns validation, recording identity, scene snapshots and collection color precedence. Explicitly selecting an inheriting collection must inherit the scene/default even when another membership has a color. Provider privacy choices are global and never stored in song scenes. Clock scale is 70–140%; older 60–180% stored values migrate into this range. New collection names are unique without case/diacritic differences and contain 1–40 Unicode characters.

`src/app.js` owns UI state and `notice()` is the shared accessible status surface. The app's existing native HTML `dialog` owns modal focus, Escape and background isolation; deletion extends that owner through an app-owned dialog naming the collection, consequence and explicit Delete/Cancel actions. Cancel is focused first. Inputs retain invalid drafts, expose `aria-invalid` and focus the offending field.

`src/bridge.js` owns native invocation and the explicitly silent browser preview. Browser checks establish shared UI behavior; they do not certify WebView2, clipboard, native dialogs, real players, system audio, Explorer wallpaper or suspend/wake. Windows-specific copy must name Windows media sessions and native shortcut registration and must not direct Windows users to Linux compositor or MPRIS setup.


Windows parity work extends these same owners: `lyric-retry.js` owns bounded 15/45-second missing-synced retries with fake-timer cancellation checks. `domain.js` owns the Mac preset RGB palette, deduplicated named swatches, album-cover collection mode and recording-specific selected lyric documents. Appearance and Collections reuse the actual playback renderer with provider timestamps and current-song timing; they never display sample lyrics. A single parent tick draws their preview at a maximum 15 Hz (10 Hz on battery); its ResizeObserver is disconnected on tab change/close. The preview is explicitly marked Live/Paused and represents the current song's effective appearance. Independent Full Screen uses the native window API separately from Focus composition.


Windows 0.1.1 repairs the shared Appearance surface to follow the existing Mac reference: an at-most 800 × 700 glass dialog with a 256-point preview/wallpaper column and a fluid color/screen column. Header, navigation and Done stay outside the single body scroller. At small viewports the dialog is bounded by the available width/height. `appearance-sky.js` translates Mac Theme.appearanceSkyColors (saturation capped at 0.40; brightness 0.16/0.28/0.52); the effective lyric/album/collection RGB is its sole hue input. `style.css` owns glass opacity, blur, dimensions and global scrollbar tokens. Native HTML select/input and dialog semantics remain canonical.

`notice.js` owns one cancellable, deduplicating status timer; `app.js` owns its accessible status host and re-parents it into the active dialog's top layer. Information lasts five seconds, errors eight; hover/focus pause expiry and Dismiss clears immediately. Critical library-load failures also remain in the Controls warning, so transient feedback never hides preservation/save-disabled information. Footer song metadata never becomes a persistent error banner.

The shared renderer passes the actual canvas width and height to `ribbonMesh`, which owns all coordinates, including reduced-motion amplitudes. No Mac-sized transform or second coordinate scale remains. Capture continues in Controls and its real preview; pause, visibility, sleep, explicit disable and player changes retain lifecycle guards. Explicit stream changes stop the prior capture before setting the next process identity. Windows WASAPI uses event-driven process-loopback capture with a system-selected buffer size, following Microsoft's SDK sample; it never falls back to recording the system mix.


Windows 0.1.2 adopts the supplied Mac footer reference: centered title/artist and a narrow elapsed/progress/duration row, without artwork, transport buttons or beat diagnostics. `listening-footer.js` is its shared owner for the app and read-only, click-through wallpapers. Transport and collection actions remain in Controls > Player; Space toggles playback when the listening surface has focus. Native range semantics and keyboard seeking remain available in the app.

Each wallpaper owns playback/word interpolation through `desktop-state.js`, consumes native audio-frame/power events directly, stops stale audio after 300 ms, and pauses on system sleep. Main-window deltas carry real provider timestamps and sample positions. The native `Display` cache merges preference deltas and sends a complete snapshot after the wallpaper registers its listeners. The same ready handshake controls first visibility; a blank/unready renderer cannot silently hide the only available controls.

Windows Desktop owns one physical-monitor-sized, click-through child for each connected screen, with Explorer-matched DPI awareness. It supports both legacy WorkerW and raised Progman/DefView layers, and rebuilds after host loss or monitor/DPI changes. A generation guard prevents stale recovery from re-enabling a stopped session. Controls can be reopened while wallpaper continues; rebuilding never hides controls the user has reopened. After repeated attachment failure it restores the main window and reports the problem. Reference API constraints: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent ; layout evidence: https://github.com/rocksdanister/lively/blob/core-separation/src/Lively/Lively/Core/WinDesktopCore.cs .

Beat sync has an explicit session-only switch. `audio-source.js` chooses a single recognized Spotify/Apple Music executable or a previously explicitly selected executable; multiple candidates and browser tabs require explicit stream selection. Stream restarts may reconnect with the same consent, while player changes clear it. Status reflects setup, received signal, silence, stale frames and recoverable errors; a successful start call alone is never labelled listening.
